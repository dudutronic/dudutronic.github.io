AI SKILL · PROJETO EM DESTAQUE OFFLINE · HEURÍSTICAS LOCAIS

QA Copilot Skill

PoC local em Python para rascunhar cenários BDD, analisar assinaturas conhecidas em logs de automação e gerar payloads sintéticos a partir de contratos JSON. Requisitos, logs e dados não saem da máquina.

Python Robot Framework Cypress Appium BDD / Gherkin API Testing

COMO EXPERIMENTAR

Execute os comandos dentro da pasta qa-copilot-skill/. Para rodar tudo de uma vez:

python -m qa_copilot_skill.cli demo
  1. 01
    BDD / GHERKIN

    Informe uma história de usuário; receba um fluxo principal e sugestões de validação.

    python -m qa_copilot_skill.cli bdd --requirement "Como cliente, quero consultar meu saldo para acompanhar meus gastos." Saída: três cenários em Dado / Quando / Então; casos sem critérios ficam marcados para revisão.
  2. 02
    TROUBLESHOOTING DE LOGS

    Analise o exemplo sanitizado de uma falha Cypress.

    python -m qa_copilot_skill.cli troubleshoot --log-file examples/cypress_failure.log Saída: framework provável, causa e próximos pontos para investigar.
  3. 03
    PAYLOAD DE API

    Gere dados sintéticos usando o contrato JSON de exemplo.

    python -m qa_copilot_skill.cli payload --contract examples/api_contract.json --seed 42 Saída: JSON com valores reproduzíveis para testes de backend.

Na rotina de QA, acelera o primeiro rascunho de cenários e massas de teste e ajuda a direcionar o troubleshooting em CI/CD — conectando Python, Robot Framework, Cypress, BDD e testes de API.

PoC baseada em regras, sem LLM ou chamadas externas. As sugestões exigem revisão humana; use apenas logs sanitizados e dados sintéticos.

AUTOMAÇÃO DE TESTES · PROJETO EM DESTAQUE ↗ PESSOAL

Musi Playwright BDD

Uma suíte de testes end-to-end que combina Playwright, TypeScript e Cucumber para validar fluxos com cenários legíveis, relatórios com evidências e execução automatizada no GitHub Actions.

TypeScript Playwright Cucumber BDD CI / GitHub Actions

COMO O PLAYWRIGHT FOI CONFIGURADO

  • TypeScript + Page Objects: ações e seletores organizados por página.
  • Cucumber BDD: perfis smoke e regressão; execução por tags.
  • Execução isolada: contexto novo por cenário, navegador selecionável e evidências de tela/vídeo.
  • GitHub Actions: Node 20, verificação de tipos, smoke e relatórios como artefatos.
  • Relatórios: resumo JSON, relatório HTML por execução e evidências de tela/vídeo.

BACK-END HTTP · ROBOT FRAMEWORK ↗ PESSOAL

Musi Robot HTTP Smoke

Uma terceira suíte que valida, por HTTP e sem alterar dados, a disponibilidade e o conteúdo das rotas públicas de login e cadastro. Complementa os testes de interface com uma checagem direta das respostas do servidor.

Python Robot Framework RequestsLibrary GitHub Actions

COMO O ROBOT FRAMEWORK FOI CONFIGURADO

  • Page Object para HTTP: um resource reutilizável encapsula sessão, rotas e validações.
  • RequestsLibrary: confere status HTTP, tipo HTML e título esperado das páginas públicas.
  • Execução segura: somente GET em /login e /register; sem login, POST ou criação de dados.
  • GitHub Actions: Python 3.13, dependências fixadas e relatórios Robot publicados como artefatos.
  • Relatórios: report.html, log.html e output.xml em robot-results/.
